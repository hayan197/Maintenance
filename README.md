# تطبيق FixFlow للعميل (Flutter) — MVP

هذا الكود يغطي شاشة تسجيل الدخول، قائمة الطلبات مع الإحصائيات والفلترة،
إنشاء طلب جديد، وتفاصيل الطلب مع الإلغاء — متصل مباشرة بنفس الـ API الذي
يخدم لوحة العميل على الويب (`api-contract.md` في مشروع Laravel).

## لماذا لازم تشغّل `flutter create` بنفسك؟

بيئة التنفيذ التي كتبت فيها هذا الكود لا تملك Flutter SDK ولا اتصال إنترنت،
لذلك ما قدرت أشغّل `flutter create` (اللي يولّد مجلدات `android/` و`ios/`
والملفات الأساسية الخاصة بكل منصة) ولا `flutter pub get` ولا `flutter analyze`
للتأكد الآلي من عدم وجود أخطاء. راجعت كل ملف يدويًا (توازن الأقواس، أسماء
الحزم، أسماء الـ parameters) بعناية، لكن ينصح تشغّل الأوامر أدناه عندك قبل
أي اعتماد على الكود.

## خطوات التشغيل

```bash
# 1) أنشئ مشروع Flutter فارغ (يولّد android/ و ios/ وملفات المنصة)
flutter create --org com.fixflow --project-name fixflow_customer fixflow_customer_app
cd fixflow_customer_app

# 2) احذف pubspec.yaml ومجلد lib الفارغين اللذين أنشأهما flutter create
rm pubspec.yaml
rm -rf lib

# 3) انسخ pubspec.yaml ومجلد lib المرفقين هنا مكانهما
cp /path/to/fixflow_customer/pubspec.yaml .
cp -r /path/to/fixflow_customer/lib .

# 4) نزّل الحزم
flutter pub get

# 5) شغّل على محاكي أو جهاز
flutter run
```

## إعداد رابط الـ API

افتراضيًا الكود يشير إلى `http://10.0.2.2:8000/api/v1` (وهو العنوان الذي
يستخدمه محاكي أندرويد للوصول إلى `localhost` على جهاز التطوير). لتغييره:

```bash
# عند التشغيل المحلي على جهاز/محاكي iOS، استخدم IP جهازك الفعلي بدل 10.0.2.2
flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8000/api/v1

# عند النشر الفعلي، وجّهه لدومين الإنتاج
flutter run --dart-define=API_BASE_URL=https://api.yourdomain.com/api/v1
```

## ملاحظة مهمة على الباكيند

الباكيند (`maintenance-center-laravel`) يجب أن يكون شغّالاً ومتاحًا على
الشبكة (`php artisan serve --host=0.0.0.0`) حتى يقدر المحاكي/الجهاز
الوصول له. تذكّر أيضًا أن `POST /api/v1/login` (المسار المستخدم من هذا
التطبيق) يصدر Bearer token حقيقي — لا علاقة له بجلسة الويب المستخدمة في
لوحة العميل على المتصفح، فكل مستخدم/جهاز يحصل على توكن مستقل.

## ما هو مبني الآن (MVP)

- تسجيل الدخول وحفظ التوكن بأمان (`flutter_secure_storage`) لتسجيل دخول
  تلقائي عند إعادة فتح التطبيق.
- قائمة "طلباتي" مع إحصائيات (مفتوحة / قيد التنفيذ / مكتملة)، فلترة حسب
  الحالة، وترقيم صفحات.
- إنشاء طلب جديد مع إظهار حقل "جهة اتصال الطوارئ" تلقائيًا عند الحاجة،
  وعرض أخطاء التحقق القادمة من السيرفر تحت كل حقل.
- تفاصيل الطلب (بيانات كاملة + عناصر الفاتورة إن وجدت) وإلغاء الطلب.
- تسجيل الخروج (يبطل التوكن في السيرفر عبر `POST /api/v1/logout`).

## ما لم يُبنَ بعد (خارج نطاق الـ MVP)

- الإشعارات الفورية (Push notifications) عند تغيير حالة الطلب.
- تتبع موقع الفني على خريطة.
- تعديل الطلب بعد إنشائه (الشاشة الحالية تدعم الإنشاء والإلغاء فقط، تمامًا
  كما في نسخة الويب).
- أيقونة التطبيق والشاشة الافتتاحية (Splash) المخصصة — حاليًا افتراضيات
  Flutter.
